## Teacher workflow

The existing sidebar link and historical `curriculum-tracker` route remain valid. After selecting the academic period, the teacher selects an assigned class/stream and learning area. The selected context remains visible inside the planner. Existing school branding, form styles, lesson-plan modal, preview and print component are reused.

Stored suggested learning experiences now survive PostgreSQL reads, and this planner rejects cross-area/cross-grade catalogue fallbacks instead of treating aliases as verified links. The term allocation screen groups the actual curriculum catalogue into strands and sub-strand cards. It calculates included/available strands, included/available sub-strands and allocated/available lessons separately. A valid plan may cover a subset of the catalogue. Below- and above-capacity drafts persist, without inventing extra periods; the UI explains remaining or excess lessons. Teachers can reduce one allocation and increase another, or explicitly combine sub-strands into shared lessons. Combined lessons count once against capacity while each constituent sub-strand counts toward coverage. They can separate a combined sub-strand again before finalizing. Additional teaching time requires an administrator to change the actual timetable.

A published term calendar and an active matching timetable are mandatory for drafting. Eligible slots are recalculated from current schedules on reads and mutations, on explicit refresh, and when returning to the app. Cancelled dates/periods cannot finalize or create new lessons. Calendar/timetable changes preserve saved allocations, historical entries, lesson plans and teaching records, and identify stale slots/numbering. An invalidated saved plan remains locked until explicitly reopened.

## Two different locks

- **Saved-plan lock:** finalization validates all slots and required content, records a revision/history event and freezes allocations. A matching total is insufficient: duplicates, cancellations, missing slots and invalid content fail. Reopening requires an authorized owner or existing supervisory role, an explicit action and a reason recorded in history. Lesson planning, taught records and reflection remain available for eligible slots while allocations are locked. Legacy parallel schemes and teacher/profile ID aliases cannot bypass the area’s saved-plan lock.
- **Sequence lock:** when configured, the previous learning area must have a submitted/approved, validated complete scheme. New allocation plans must also be finalized/locked. Reopening or invalidating the previous scheme locks the next area again. This is checked in the backend, including catalogue entry, direct scheme URLs, mutations and exports.

When finalized allocations replace previous entries, old entry IDs/content remain archived. Existing taught records continue to refer to their actual lesson plan, original entry, date and period. Unchanged curriculum/slot entries retain their IDs. Finalization checks both the allocation revision and existing entry snapshot to reject stale concurrent changes.

## Weekly lessons and exports

The weekly screen is derived from eligible dates and periods, with Previous, Next and a date-range selector. Week ranges follow the actual eligible dates. Each card has independent Planned, Taught and Reflection states. Planned requires a complete lesson plan with timed activities; a teaching record changes Taught; a saved nonempty post-lesson reflection changes Reflection. Saving one does not set the other two. Lesson curriculum/date/time remain tied to the schemed slot.

The linked lesson workflow reuses the existing lesson-plan form and six-column School / Level / Learning Area / Date / Time / Roll preview/print template. Revised lesson drafts preserve earlier lesson plans and teaching links. Phone controls provide Options, history/reopening and weekly exports. Both PDF and native Word `.docx` are generated by backend endpoints from the same authorized weekly data; neither contains reference screenshots. Exports include the actual scheduled slots, curriculum content and independent statuses, and use private/no-store responses.

## Authorization and routes

Ordinary teachers require active school/year/term assignments, the applicable class/stream/learning area and private-work ownership. Class teachers use existing class assignment rules. Administrators/headteacher/deputy roles retain existing supervisory access. A Grade 2-only teacher cannot read, edit, reopen, finalize or export Grade 3 work. A subject/stream teacher cannot access another subject’s private work, another stream or another teacher’s scheme.

New/reused endpoints under `/api/v1/curriculum`:

| Endpoint | Purpose |
| --- | --- |
| `GET /planning/options`, `/planning/workspace`, `/planning/slots` | Existing assignment-filtered context and current schedules |
| `GET /planning/catalogue` | Authorized and sequence-gated strands/sub-strands |
| `PUT /planning/allocations` | Save below/above-capacity allocation draft |
| `GET /schemes/:id/allocations` | Current allocation state, progress and conflicts |
| `POST /schemes/:id/finalize` | Validate and lock allocations |
| `POST /schemes/:id/reopen` | Explicit authorized reopen with reason |
| `GET /schemes/:id/history` | Allocation snapshots, actors, actions and reasons |
| `GET /schemes/:id/weekly` | Actual weekly lesson cards and separate statuses |
| `GET /schemes/:id/weekly/export?format=pdf\|doc` | Protected PDF or native Word download |
| `POST /lesson-plans`, `PUT /lesson-plans/:id/reflection` | Linked lesson creation and post-lesson reflection |
| `POST /planning/record-taught` | Existing linked teaching record workflow |

## Web teacher class visibility fix

A valid class-wide or subject assignment could therefore leave the dashboard without a class name or stream. The authorized-context endpoint also used older, inconsistent rules for periods and Grade 4+ subjects. It now uses `TeacherAssignmentAccess` for the selected year and term, returns authorized streams and subjects per stream, and ignores legacy profile caches as permission sources. Class teachers retain their class subject overview even where another subject teacher is assigned. Subject teachers retain only their assigned areas and streams; private curriculum ownership checks remain in force.

The web dashboard now includes My Classes, a class/stream selector, learner and subject counts and learning-area names. The roster follows the selected cohort and Profile opens the selected learner. Shared backend authorization supports the web requests. Teacher startup no longer requests school-wide finance analytics or payments.

A second defect rejected a class-wide teacher when attendance supplied only a stream ID. Attendance now uses the common assignment policy, which resolves the stream's class and respects the assignment period.
